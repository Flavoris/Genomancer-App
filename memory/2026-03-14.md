## Work Completed
- Found a concrete tokenizer bug in `sample_tokenizer_corpus()`:
  - it only sampled one window per FASTA record
  - large genomes therefore contributed a single slice to BPE training
  - tokenizer vocab quality was lower than expected for whole-genome pretraining
- Fixed tokenizer corpus sampling to:
  - sample windows with replacement
  - weight sequence selection by contig/genome length
  - keep sampling until `tokenizer_max_bases` / `tokenizer_max_sequences` budgets are actually reached
- Extended tokenizer metadata matching so existing tokenizer files are retrained when corpus-sampling settings change:
  - `tokenizer_window_size`
  - `tokenizer_max_bases`
  - `tokenizer_max_sequences`
- Reduced default tokenizer corpus budgets in `pretrain.yaml` because the current pure-Python BPE trainer is intentionally simple and should not be asked to process tens of millions of bases.
- Added transformer-side optimization fixes:
  - embedding `LayerNorm`
  - BERT-style small-std initialization for embeddings, linear layers, attention projections, and MLM head parameters
- Added/updated regression tests for:
  - multi-window tokenizer corpus sampling from a single long sequence
  - tokenizer retraining on corpus-sampling metadata mismatch
  - transformer embedding normalization / pad-row initialization
  - MLM model tied/untied head behavior
